# Testing & Pre-Release Verification (`docs/testing.md`)

Sooyo uses three focused testing tiers managed via `pnpm` and a single browser automation framework (**Playwright Test**).

## 1. The Three Testing Tiers

| Tier | When to Run | What It Verifies | Runner |
|---|---|---|---|
| **Lightweight CI** | Every push to `main` / PR | Syntax, import rules, UTF-8 integrity, 226+ offline protocol/recovery/sync/CSS checks | GitHub Actions (`ubuntu-latest`, single job) |
| **Real DSH E2E + Visual Verification** | UI, Sync, Storage, or Agent changes | Installs packaged plugin into isolated `DSH_HOME`, drives real DSH Web Host via Playwright, saves screenshots for coding Agent review | Local developer / coding Agent |
| **Pre-Release Smoke** | Before publishing a new version | Clean install, `pnpm pack` bundle verification in isolated DSH, core UI + Hub/Client sync E2E, Desktop/Mobile screenshot inspection | Local developer / coding Agent |

## 2. Commands

```sh
pnpm install --frozen-lockfile
pnpm run check                                      # syntax + no-bare-imports + UTF-8 check
pnpm run test:offline                               # fast offline self-test (protocol, Intent ledger, Outbox, backup, CSS guards)
pnpm run test:e2e                                   # full real-DSH Playwright E2E suite (ui + sync)
pnpm exec playwright test tests/e2e/ui.spec.mjs     # single-instance real DSH UI, persistence & Desktop/Mobile screenshots
pnpm exec playwright test tests/e2e/sync.spec.mjs   # two-instance real DSH Hub + Client sync E2E
```

## 3. Real DSH E2E Architecture (`tests/e2e/`)

- **`tests/e2e/dsh-fixture.mjs`**:
  - Runs `pnpm pack` once and installs the resulting `.tgz` bundle into an isolated temporary `DSH_HOME` via `dsh plugin --profile web add <tgz>` — never touching `~/.dsh` or any running developer DSH process.
  - Starts `dsh --profile web --no-open --host 127.0.0.1 --port 0 --patch <overlay>`, captures the `dsh web: <authenticatedUrl>` startup URL (redacting the token from logs), and waits for `/sooyo/ping` readiness.
  - Fails explicitly if `@deepseek-ai/dsh` or Chromium is unavailable — never silently skipping E2E tests.
- **`tests/e2e/ui.spec.mjs`** (Single DSH instance — `E2E-1`, `E2E-2`, `E2E-3`, `E2E-5`):
  - **E2E-1**: Opens real DSH Web UI, activates the `sooyo daily` panel from `sidebar.panellist`, asserts zero `pageerror` and default Boards (`总览`, `工作`, `生活`, `阅读`).
  - **E2E-2**: Creates Todo & Note, verifies unknown Widget Type (`timeline2028`) read-only placeholder, verifies self-contained Read Later snapshot (`readLaterEntries`), and tests interactive Agent Inbox Proposal (`preview.diff` badge → Approve → Rollback).
  - **E2E-3**: Verifies user data and layout survive both browser reload (`page.reload()`) and a full DSH process restart (`dsh.restart()`).
  - **E2E-5**: Asserts `ov=0` (`scrollHeight - clientHeight <= 1`) on every card and zero horizontal overflow at Desktop (`1440×900`, light/dark) and Mobile (`390×844`, dark/light), saving screenshots to `test-results/screenshots/`.
- **`tests/e2e/sync.spec.mjs`** (Two DSH instances — `E2E-4`):
  - Boots an isolated Hub DSH (`role: 'hub'`) and an isolated Client DSH (`role: 'client'`), verifying cross-instance synchronization and idempotent command replay with zero duplicate records.

## 4. Pre-Release Smoke Checklist

Before tagging or releasing a new plugin version, run and record the following locally:

1. `pnpm install --frozen-lockfile && pnpm run check && pnpm run test:offline`
2. `pnpm run test:e2e` (verifies `pnpm pack` release tarball installation in isolated DSH, `E2E-1` through `E2E-5`)
3. Open and visually inspect at least the Desktop (`test-results/screenshots/dsh-desktop-1440-light.png`) and Mobile (`test-results/screenshots/dsh-mobile-390-dark.png`) screenshots generated by Playwright.
4. Record in the commit or release description:
   - Exact commands executed and pass/fail counts
   - Tested `dsh --version`
   - Any items not covered
